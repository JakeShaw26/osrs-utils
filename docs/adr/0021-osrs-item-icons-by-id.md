# ADR-0021: OSRS item icons by item id, served from our own origin

- **Status:** Accepted
- **Date:** 2026-08-01
- **Deciders:** Repository owner (the licensing call), AI agent (the mechanism)
- **Extends:** [ADR-0007](./0007-api-first-no-code-redistribution.md) — which
  governs third-party **code** and never considered artwork

## Context

The hand-drawn feature sprites shipped in [ADR-0020](./0020-nero-marquina-visual-direction.md)
were reviewed by the owner and rejected on quality. Every OSRS tool in the wild
— the wiki itself, Wise Old Man, TempleOSRS, every DPS calculator — displays the
game's own item icons instead. The economy, drop-table and clue-reward features
all want an icon per item id, so this needed a general answer rather than seven
replacement drawings.

### What was measured, 2026-08-01

- **The price mapping carries the filename.** `/api/v1/osrs/mapping` returns an
  `icon` field for **all 4,650** items: `{"id": 4151, "icon": "Abyssal whip.png"}`.
  **[VERIFIED]**
- **Deriving that filename is wrong for 294 items (6.3%).** `Acorn` is drawn by
  `Acorn 5.png`; `Abyssal bracelet(5)` by `Abyssal bracelet.png`. Every failure
  is a silent 404, not an error. **[VERIFIED]** — this is a page-name trap of
  the same family as `Salve amulet(i)`.
- **Icons are trimmed to content, not gridded.** Widths run 18–36 and heights
  29–32; the maximum across the full set is exactly **36×32**, the game's
  inventory cell. There is no fixed grid to scale against. **[VERIFIED]**
  ⚠️ A partial sample topped out at 32×31 — sizing the cell from measurement
  alone would have clipped the widest icons. The cell is 36 because that is the
  game's, not because that is what a sample showed.
- **They are tiny:** mean 516 bytes, **2.29 MB** for 4,646 files. **[VERIFIED]**
- **Four of 4,650 mapping rows name an icon file that 404s** (`Crystal 2h axe`,
  `Trinket of vengeance (1)` and (2), `Crystal 2h axe (inactive)`). The mapping
  is authoritative about the _filename_, not about the file existing.
  **[VERIFIED]**
- **Files resolve at `https://oldschool.runescape.wiki/images/<Underscored_Name>`**,
  including the awkward cases (`+`, apostrophes, brackets). **[VERIFIED]**

### The licensing position

- **Wiki images are not CC BY-NC-SA.** Text is; [RuneScape:Images](https://oldschool.runescape.wiki/w/RuneScape:Images)
  states images are _"used under the fair use license"_ and remain Jagex's
  property. **Fair use is a defence, not a licence** — it is assessed per use and
  does not transfer to us. **[VERIFIED]**
- **Jagex T&Cs §6** forbids users to _"share or make available to any person"_
  the Jagex Product, without a commercial qualifier. A strict reading forbids
  this regardless of how we source it.
- **The npm package route does not help.** [`@dava96/osrs-icons`](https://github.com/Dava96/osrs-icons)
  ships ~19,500 icons under CC BY-NC-SA 3.0 while its own README states _"Icons
  are the property of Jagex/OSRS Wiki"_ — it cannot license what it does not
  own. Installing it changes the delivery mechanism, not the copyright.
- **So no sourcing route is clean.** What makes this acceptable is the position
  [`api-terms.md`](../api-terms.md) §1 already records for the hiscores:
  **"Tolerated ≠ licensed. We rely on Jagex's forbearance."** This extends that
  bet from data to art. The mitigations are unchanged and already in force:
  non-commercial, no ads, attribution in the footer, unaffiliated disclaimer.

**The owner made this call explicitly**, having been shown that the "it is only
a personal project" framing does not hold: this app is public and read-only
([ADR-0012](./0012-no-authentication-public-read-only.md)), so serving an image
to a visitor is distribution and public display whatever the motive.

## Decision

**We will display Jagex's own item icons, sourced by item id, served
same-origin, and generated by one hand-run script. The icons themselves are
_not_ committed.**

1. **`scripts/generate-item-icons.mjs` is the only writer.** It reads the `icon`
   field from `/mapping` — **never** derives a filename from an item name — and
   emits `src/lib/ui/item-icons.generated.ts`, an id manifest.
2. **The generator is hand-run, incremental and throttled** (~8 req/s, one
   retry, widening backoff on 403/429). It must never run in CI or at build.
3. **Icons are served same-origin only.** No `<img>` in this repo may point at
   the wiki — hotlinking is ruled out by [`api-terms.md`](../api-terms.md) §2
   rule 7.
4. **`ItemIcon` is a separate atom from `Sprite`**, not a re-skin of it. Same
   tier conceptually — fixed palette, untintable, needs `slotted` on dark — but
   a fixed _cell_ with natural-size artwork inside, because there is no grid.
   Scale is `1 | 2`; non-integer scaling makes nearest-neighbour wobble.
5. **Hard rule #9 gains an explicit carve-out.** "Never copy third-party source
   into this repo" stands for code. Item artwork obtained from a published
   game-data endpoint and used non-commercially is permitted **only** under this
   ADR. The manifest — ids, no pixels — is ordinary data and carries none of
   this weight.
6. **`public/item-icons/` is gitignored.** The owner declined 4,646 binaries in
   the repository. This was the option originally rejected below, and the
   trade it makes is recorded honestly in the next section rather than
   presented as a win.

## ⚠️ Delivery is unresolved, and nothing ships until it is

> **RESOLVED by [ADR-0022](./0022-item-icon-delivery-packed-atlas.md)** (same
> day). The atlas option below was taken, sharded into ten sheets and committed.
> Two figures in this section turned out to be wrong: the atlas is **0.81 MB,
> not ~2 MB**, and sharding it costs nothing, so the "whole-atlas download for
> three icons" objection does not apply. The section is left as written — it is
> the record of what was known at the time. **Its consequences below are stale
> in one respect: "making the repo public stays cheap" is no longer true**, and
> ADR-0022 says why.

Not committing the PNGs does not merely leave a directory untracked — **it
leaves the app with no icons anywhere except the machine that ran the
generator.** A fresh checkout (CI, any deploy) renders empty cells, and the
disk-coverage assertions in `ItemIcon.test.tsx` skip because their subject is
absent.

The three candidates, none yet chosen:

| Option                                      | Cost                                                                                                                                         |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **One packed atlas + offset map** (2 files) | Satisfies the file-count objection exactly and keeps the build offline. Costs a whole-atlas download (~2 MB) for a page showing three icons. |
| **Generate at build**                       | ~4,600 wiki requests per build. Ruled out by `api-terms.md` §2 unless heavily cached.                                                        |
| **Object storage at the host**              | Clean, but needs infrastructure and **V13 (hosting) is still open**.                                                                         |

**The atlas is the likely answer**, because the owner's objection was file
count, not bytes and not licensing — and an atlas is the only option that
answers file count without moving the cost onto the wiki. Decide before wiring
`ItemIcon` into any route.

## Consequences

### Good

- **The icons are the game's own**, so the app stops looking like an imitation of
  OSRS and starts looking like a tool for it.
- **Nothing is fetched at request time**, so no rate limiter, no cache and no
  open-proxy surface — the failure mode [PRD §5.3](../../PRD.md) warns about
  cannot arise for icons.
- **No third-party artwork in git**, so hard rule #9 survives almost intact and
  the repo stays free of 4,646 undiffable binaries.
- **⚠️ Making the repo public stays cheap.** Had the icons been committed, the
  branch-protection option in HANDOFF.md ("make the repo public") would have
  turned into publishing a Jagex art mirror. It does not, so that option is
  still on the table at its original price.
- The `icon` field removes a 294-item bug class before it was ever written.

### Bad

- **The app has no icons anywhere except the generating machine.** This is the
  dominant cost and it blocks every feature that would use them. See "Delivery
  is unresolved" above.
- **Two guards go quiet.** `ItemIcon.test.tsx`'s disk-coverage assertions skip
  without their subject, so the drift they exist to catch — a manifest naming a
  file nobody wrote — is currently unguarded. Marked provisional in the test.
- **The generator's output is now invisible to review.** A bad run that fetched
  garbage would be caught by nothing, where a commit diff would at least show
  4,646 changed blobs.
- **The set goes stale silently.** New items appear on game updates and nothing
  notices; `ItemIcon` renders an empty cell, which looks like a design choice
  rather than a missing asset.
- **Regeneration is a ~10-minute hand-run**, so it will be forgotten — and now
  every contributor must run it, not just the one who first added the icons.

### Neutral

- `ItemIcon`'s manifest (~4,600 ids, ~28 KB source) reaches the client bundle if
  a Client Component imports it. Server Components pay nothing. Acceptable now;
  revisit if a client-side item table ships.
- The seven hand-drawn `Sprite`s stay — they name _tool groups_
  (Economy, Combat…), which no single item icon represents.

## Alternatives considered

| Alternative                                 | Why not chosen                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`@dava96/osrs-icons` npm package**        | The genuinely close option — zero effort, auto-updated from the wiki. Rejected on two counts: its CC BY-NC-SA grant is one it does not hold, so it adds a false sense of cover; and base64-inlining 19,500 icons puts artwork in the JS bundle rather than in cacheable image files. **Would win** if it shipped real image files and dropped the licence claim. |
| **Hotlink to the wiki**                     | Zero storage and always current. Ruled out by `api-terms.md` §2 rule 7 — it spends their bandwidth on our traffic on every page view, and makes every page render depend on their uptime.                                                                                                                                                                        |
| **Commit all 4,646 PNGs**                   | Robust, offline builds, keeps every guard live — and this ADR originally chose it. **Rejected by the owner: 4k binaries is too much repo churn.** That is a legitimate call; it simply relocates the problem to delivery rather than removing it.                                                                                                                |
| **Gitignore, generate at build**            | Keeps artwork out of git and hard rule #9 literally intact. Rejected: a fresh CI checkout re-downloads ~4,600 files per build, which is abusive in exactly the way we tell ourselves not to be.                                                                                                                                                                  |
| **Gitignore + GitHub Actions cache**        | Polite _and_ keeps art out of git. Rejected for the failure mode: a cache miss silently ships a site with no icons, and "silently correct-looking" is the defect shape this project keeps being bitten by.                                                                                                                                                       |
| **Runtime proxy route, cached at the edge** | Narrower than a general proxy (fixed id→URL map, no caller-controlled URL). Rejected: it reintroduces rate limiting and an upstream dependency for assets that never change per request.                                                                                                                                                                         |
| **Keep the hand-drawn sprites**             | No licensing question at all. Rejected by the owner on quality, and it does not scale — drop tables need an icon per item, not per tool group.                                                                                                                                                                                                                   |

## Revisit if

- **Jagex or the OSRS Wiki objects**, by takedown or by blocking our User-Agent →
  remove the icons and fall back to `Sprite`; keep the fallback path working.
- **Making the repo public is seriously proposed** → re-read the Bad section
  first. Prefer paying for GitHub Pro over publishing the artwork.
- **The project is ever commercialised** → this ADR dies with Jagex §6 and the
  wiki's CC-NC; both foreclose it independently.
- **Icons drift far enough to be visibly wrong** → automate the regeneration
  check, rather than trusting anyone to remember it.
- **A client-side item table ships** and the 28 KB manifest starts mattering →
  split it, or move the existence check server-side.
